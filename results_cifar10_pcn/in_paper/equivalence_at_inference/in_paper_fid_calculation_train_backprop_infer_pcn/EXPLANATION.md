## 1. Claim

A network trained conventionally by backprop can be run as a PCN whose
relaxation computes the velocity, with no loss in sample quality. Same weights
on both sides of each row; the source of −∇_x V at each integration step is the
only difference.

**Selection rule (this is what shows the samples are not cherry-picked).** The
FID runners stream generated images into the FID state and store none, so these
were regenerated with the same seed and settings. The runner seeds
`manual_seed(fid_seed*1000 + rank)` and draws its first batch as
`randn(128,3,32,32)`; a 1-GPU run at the same `fid_seed` reproduces rank 0's
stream (`fid_cifar_heun_1gpu.py:327-331`). **The figures show the FIRST 32
(figure E) and FIRST 16 (figure F) of that batch, in order** — captions say "the
first 32 of the seeded batch". All 128 of the batch are saved in the `.npy`
files, so any other block is available, but no per-image selection was made.

**Batch size is load-bearing**: torchsde draws the Brownian path over the whole
flattened (B, D) state, so generating 16 images directly would NOT reproduce the
first 16 of a 128-batch. Always regenerate the full batch and slice.

**Matched-seed agreement** (figure F, 16 shown): mean |Δpixel| 10.8/255, max
89/255, per-image correlation 0.904–0.992 (median 0.961). Unrelated baseline
(sample i vs i+1 of the same run): 131/255 and correlation 0.104. So the pairs
are the same picture; they are not pixel-identical, because a ~1e-7 relative

## 4. Definitions

- **Matched seed**: both samplers run with `--fid_seed=1`, which seeds the
  generator noise; the same realisations therefore drive both. Paired this way
  the phase-1 difference is 0.001 FID — three orders of magnitude below the
  0.03 seed-to-seed spread that is common to both columns.
- **Phases**: phase 1 = the transport-only warm-up (145k steps of our Energy
  Matching replication); phase 2 = its contrastive-divergence continuation
  (147k). τ_s is the sampler's terminal integration time.
- **PCN settings that actually govern the sampler**: γ_code = 0.1 (γ_V = 1e-4),
  K_h = 1, dt = 1.0, EMA weights — plus `energy_clamp` on ImageNet-32. The
  inference path is `velocity()` → `_velocity_error_param()` → `relax_errors(x,
  gamma, K_h, dt_relax)` (`network_pcn.py:1424,1457`).
- **Flags the scripts pass that are INERT at inference**: `--T_free` and
  `--pcn_cg_steps`. `T_free` is read only by `_velocity_ep_spring`
  (`network_pcn.py:1462`), reached only when `param_grad_mode == "ep"` during
  training or via an explicit `velocity_mode="spring"`; our FID runs pass
  `--param_grad_mode=ift`, so it never executes. `pcn_cg_steps` drives CG only
  inside `IFTEquilibriumHiddens.backward`, attached only when training.
  **Verified numerically** (`inference_inert_flags.log`, job 34939353): varying
  T_free over 1/14/100 and n_cg over 1/3/50 moves the sampler velocity by at
  most 7.2e-7, while rebuilding the model at the SAME flags already moves it by
  4.8e-7 — i.e. every change sits at the cuDNN-nondeterminism floor. Never quote
  either as an inference setting; T_free matters only for EP *training*, where
  it is the free-phase budget (cliff at 8-10, plateau from 12).
- **Checkpoints**: `checkpoint_warmup_145000.pt`, `checkpoint_postcd_147000.pt`
  (this folder) — our backprop replication and its CD continuation.

`--fid_times=3.25` for the phase-2 row (`--fid_times=1.0` for phase 1). Backprop
side: the same command with `--model_type=ffn_unet_vit` and no PCN flags. Vary
`--fid_seed` for the seed replicates. Jobs: 34450503/34365765 phase-1 seeds
1/2/3 both samplers; 34750919 (backprop) and 34750920 (PCN) phase 2, the latter
2 nodes x 4 GPUs (`torchrun --nnodes=2 --nproc_per_node=4` with a c10d rendezvous)
because the PCN sampler takes 6.9x the backprop wall-clock: 10h48 vs 1h34 for 50k
samples on the same hardware.

**Key code.** `--ffn_checkpoint_into_pcn` routes the feedforward checkpoint
through `PCNUNetEnergyModel.load_from_ebvit` (key remap; identical parameters,
reassigned to PCN prediction functions). Velocity then comes from
`PCNVelocityWrapper.velocity` → `relax_errors` plus the envelope theorem — no
autograd velocity anywhere.

## 6. Clamp-strength convention (γ units — read before quoting any γ)

The paper states the theory in V-units: the clamp acts on the potential V with
strength γ_V, and v = −(1/γ_V) ∇_x E → −∇_x V. The CODE (and every number in
these folders) parametrizes the clamp on the pre-scale scalar o = V/α
(α = output_scale), so code γ = α·γ_V. **α is dataset-dependent**: 1000 on
CIFAR-10, 100 on MNIST — convert with the run's own α.

| code γ (as run) | γ_V on CIFAR (α=1000) | γ_V on MNIST (α=100) |
|---|---|---|
| 1.0 | 1e-3 | 1e-2 |
| 0.3 | 3e-4 (storm ceiling) | — |
| 0.1 | 1e-4 (CIFAR MAIN OPERATING POINT) | 1e-3 (MNIST VGG5) |
| 0.01 | 1e-5 (CIFAR float32-floor measurement) | 1e-4 (MNIST UNet DAG arms) |
